# Native Angband game text — Traditional Chinese (Taiwan)

This is an **incremental, display-only** localization for the bundled Angband 4.2.x native engine. The Android app already has a separate zh-TW UI translation. This document covers new *in-game* text and the parts intentionally left untouched.

## How the game decides which language to use

- `NativeWrapper.usesTraditionalChineseGameText()` consults the Android device locale and the pure Java `GameTextLocale` classifier. `zh-TW` and explicit `zh-Hant` locales use Traditional Chinese. Other locales use the original English text.
- `curses/curses.c` reads that value **once when the native plugin launches** and exposes a cached `angdroid_zh_tw_enabled()` value through `curses/droid.h`. Switching phone languages while a game is open requires a game restart to refresh this choice.
- Only the Android-managed Angband game uses the translation tables added here. The other bundled engines and variants are not yet translated.

The monster and item English names were checked against the upstream **Angband 4.2.4** `lib/gamedata/monster.txt` and `lib/gamedata/object.txt`. If a name does not match, the original English name is displayed.

Examples: `kobold → 狗頭人`, `floating eye → 漂浮之眼`, `& Dagger~ → 匕首`, `& Lantern~ → 提燈`.

## Why not translate the game data zip directly?

The Android project bundles game resources inside `app/src/main/res/raw/zipangband`. Native `monster_race.name` and `object_kind.name` are used in more places than simple screen labels. They feed English grammar, descriptions, pluralization, game lore, unidentified-item rules and potentially serialized game metadata.

**This first stage does not edit the zip, monster/object records, existing savefiles, or the logic that determines whether an item is identified.**

- The **monster list** is translated inside `get_mon_name()` for known *non-unique* monster names only. Other names, unique monsters, and the full `monster_desc()` combat narration remain English.
- The **object kind** is translated inside `object_kind_name()` only when the engine would already show the identified kind's name. Unidentified flavor labels remain unchanged. Full inventory/equipment names generated by `object_desc()` remain English.
- The localized monster/object lists now use `curses/unicode_display.h` for **two-column CJK text width**, safe whole-character clipping and byte-aware `printf` padding. Existing `unicode_width.h` remains the display-width classifier. This fixes the previous code-point-count approximation, but actual native terminal positioning and font rendering still require Android emulator testing.
- The original English menu shortcut keys, action codes, and callback bindings have not been modified.

## 2026-11-03 Android NDK format-security build fix

Android NDK r28c revealed three `-Werror=format-security` errors in
`ui-birth.c` when passing localized roller prompt fragments as the fourth
(format-string) argument to the printf-style `strnfcat()` function.
Each now passes a literal `"%s"` as the format string and passes the
localized text as the following value argument. This prevents format-string
injection and preserves the localized prompt and its existing length
accounting. The source check guards all three call sites, and the standalone
C99 text test checks the expected prompt fragments and English fallback.

A host Clang/GCC-compatible proof of the literal-format calling pattern
compiled with `-Werror=format-security`. The full Android project must still
be rebuilt on the user's SDK/NDK environment to verify the actual project.

## CJK character-sheet and dynamic-menu layout fix (2026-11-03)

The native character sheet previously used `strlen()` (UTF-8 bytes) to
measure labels and values, and even passed the byte count as the text
length to `Term_putstr()`. It now calculates terminal display columns,
clips values to whole UTF-8 glyphs and renders strings without byte-count
truncation. Race/class names are still read from unchanged English data.

The native dynamic context menu also previously sized its dialog with
`strlen()`, which could overestimate Chinese labels and result in a
negative starting column on narrow screens. It now uses display columns
and bounds the menu width to the terminal. All command shortcuts, menu
selection indices, and gameplay data stay unchanged.

These are source-level changes with a host Unicode clipping regression
test; on-device visual checking in both ASCII and tile modes is pending.

## Combat verb and critical-hit translation (2026-11-03)

Added a separate `zh-tw-combat.h` with *exact-match* melee/ranged verb

## Chinese message history scrolling and highlighting (2026-11-03)

Fixed a screen-level issue exposed by newly translated combat messages:
`ui-knowledge.c` previously advanced message text with `msg + q`,
where `q` was an offset into UTF-8 bytes. Horizontal scrolling could
therefore start from the middle of a Chinese character and show corrupted
text. Scrolling now uses whole Unicode scalars measured in terminal columns,
and search-result highlights use display-column positions rather than byte
offsets. Highlights are also clipped to whole UTF-8 glyphs at the right
edge. The zh-TW message history heading shows scrolling as columns.
The `test_unicode_display.c` host regression covers CJK boundaries and
highlight column positions.

## Narrow native action-menu column clipping (2026-11-04)

The native action-menu renderer now clips translated labels by *terminal
display columns* before calling `Term_putstr()`. Its previous width-limited
call could count input characters differently from rendered CJK cell width,
causing Chinese menu text to run into adjacent content on narrow phones.
Rendering now operates on a private temporary copy; the original
`menu_action.name` is never mutated, so callbacks and save/load behavior
continue to use original English command labels. New source and C99
regression checks guard CJK width clipping and English fallback.

## Filtered menu shortcut hints and bounded keyboard buffer (2026-11-04)

The native `ui-menu.c` soft-keyboard hint list previously used
`filter_list[0]` for every visible item while collecting selectable shortcut
keys. When an Angband menu applies a row filter, the keyboard could show a
shortcut from the wrong underlying item. It now resolves each visible index
through the filter before checking validity and finding its shortcut;
relative-row tags continue to use visible positions.

The hint buffer also used an unchecked `temp[current++]` write. Large menus
now append keys only while there is room for the final NUL byte. The original
menu selection and key dispatch behavior are unchanged. A strict host C99
regression verifies filter mappings and capacity handling; an additional
static source check guards the actual `ui-menu.c` integration in
`sh scripts/verify-zh-tw.sh`. The actual Android soft keyboard and UI
still require device-level acceptance testing.

## Narrow native multi-column menus: divide-by-zero guard (2026-11-04)

Angband's column-menu drawing and touch hit-testing previously calculated
`colw = (w - col) / cols` when the available terminal width was smaller than
the preferred columns. On a tiny phone terminal or a menu with many columns,
the result could be zero. The touch hit-test would then divide by `colw`,
which is undefined behavior and may crash.

Both code paths now call the same pure-C width helper, always returning at
least one column. Host C99 tests cover normal, narrow, zero-space and
zero-column inputs, while a static integration check ensures drawing and
hit-testing use the helper. Existing selection order, key mappings and game
records are unaffected.

This is a crash guard, **not** a complete multi-column layout redesign.
When there are more menu columns than screen cells, text can remain clipped
or too dense. A future mobile menu layout pass should reflow/paginate such
menus and must be verified on Android emulators with narrow terminal sizes.
