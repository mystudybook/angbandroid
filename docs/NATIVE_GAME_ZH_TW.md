# Native Angband game text — Traditional Chinese (Taiwan)

This is an **incremental, display-only** localization for the bundled Angband 4.2.x native engine. The Android app already has a separate zh-TW UI translation. This document covers new *in-game* text and the parts intentionally left untouched.

## How the game decides which language to use

- `NativeWrapper.usesTraditionalChineseGameText()` consults the Android device locale and the pure Java `GameTextLocale` classifier. `zh-TW` and explicit `zh-Hant` locales use Traditional Chinese. Other locales use the original English text.
- `curses/curses.c` reads that value **once when the native plugin launches** and exposes a cached `angdroid_zh_tw_enabled()` value through `curses/droid.h`. Switching phone languages while a game is open requires a game restart to refresh this choice.
- Only the Android-managed Angband game uses the translation tables added here. The other bundled engines and variants are not yet translated.

## Native gameplay translation progress

| Area | Native source | Completed |
|---|---|---|
| Character death/retirement menu | `angband/ui-death.c`, `zh-tw-death.h` | 9 menu labels, English fallback |
| Death/retirement prompts | `angband/ui-death.c`, `zh-tw-death.h` | 11 prompts, including confirmation, inventory and character dump |
| Visible/known monster list | `angband/ui-mon-list.c` | Headers, counts, sleep labels, hidden-count continuation |
| Visible/known item list | `angband/ui-obj-list.c` | Headers, item counts and hidden-count continuation |
| Common monster names in the monster list | `angband/mon-desc.c`, `zh-tw-monsters.h` | 128 exact-match normal monster names |
| Recognized object kind labels | `angband/obj-desc.c`, `zh-tw-items.h` | 76 exact-match item kind display names |

The monster and item English names were checked against the upstream **Angband 4.2.4** `lib/gamedata/monster.txt` and `lib/gamedata/object.txt`. If a name does not match, the original English name is displayed.

Examples: `kobold → 狗頭人`, `floating eye → 漂浮之眼`, `& Dagger~ → 匕首`, `& Lantern~ → 提燈`.

## Why not translate the game data zip directly?

The Android project bundles game resources inside `app/src/main/res/raw/zipangband`. Native `monster_race.name` and `object_kind.name` are used in more places than simple screen labels. They feed English grammar, descriptions, pluralization, game lore, unidentified-item rules and potentially serialized game metadata.

**This first stage does not edit the zip, monster/object records, existing savefiles, or the logic that determines whether an item is identified.**

- The **monster list** is translated inside `get_mon_name()` for known *non-unique* monster names only. Other names, unique monsters, and the full `monster_desc()` combat narration remain English.
- The **object kind** is translated inside `object_kind_name()` only when the engine would already show the identified kind's name. Unidentified flavor labels remain unchanged. Full inventory/equipment names generated by `object_desc()` remain English.
- The localized monster/object lists now use `curses/unicode_display.h` for **two-column CJK text width**, safe whole-character clipping and byte-aware `printf` padding. Existing `unicode_width.h` remains the display-width classifier. This fixes the previous code-point-count approximation, but actual native terminal positioning and font rendering still require Android emulator testing.
- The original English menu shortcut keys, action codes, and callback bindings have not been modified.

## First character creation and command menu translation (2026-11-03)

This batch adds display-only Chinese labels for character creation (quickstart,
race/class/method hints, point allocation, random rolls, name and history,
confirmation), command categories and context menu captions, savefile selection
and save prompts, textblock continuation footers and retirement confirmation.

English command descriptions in `ui-game.c` remain unchanged for lookup and
input mappings; `ui-context.c` translates them only when painting menu text.
Game data, player name rules, `CMD_*` values, menu keys and savefile formats
are unchanged. The race/class skill preview now also displays translated combat/skill
captions (without changing the calculated stats or realm names).
Chinese character-creation prompt centering measures terminal
display columns rather than UTF-8 byte lengths.

The first batch also covers common item actions, combat/action menu labels,
movement, save commands and touch context menu commands (render-only).

This is not a full Angband translation: race/class names, most combat narration,
spell messages and all other variants retain English. A host C99 test in
`tests/native/test_game_ui_locale.c` and static source checks are now part
of the local verification script; a real Android gameplay/viewport test is
still needed.

## 2026-11-03 Android NDK format-security build fix

Android NDK r28c revealed three `-Werror=format-security` errors in
`ui-birth.c` when passing localized roller prompt fragments as the fourth
(format-string) argument to the printf-style `strnfcat()` function.
Each now passes a literal `"%s"` as the format string and passes the
localized text as the following value argument. This prevents format-string
injection and preserves the localized prompt and its existing length
accounting. The source check guards all three call sites, and the standalone
C99 text test checks the expected prompt fragments and English fallback.

A host Clang/GCC-compatible proof of the literal-format calling pattern
compiled with `-Werror=format-security`. The full Android project must still
be rebuilt on the user's SDK/NDK environment to verify the actual project.

## Race and class display pass (2026-11-03)

The 11 original player-race names from `variant_lib/angband/gamedata/p_race.txt`
and the 9 original class names from `variant_lib/angband/gamedata/class.txt`
are now translated in the character-creation menu and character sheet only,
along with common character-sheet labels. Runtime race/class IDs, names in
the game's data structures and persisted savefile names are unchanged.
Other variants and class titles remain unmodified. English fallback
and representative race/class values have C99 regression coverage.

## Common gameplay screens pass (2026-11-03)

Common player-facing notices now have Traditional Chinese labels in original
Angband: empty inventory/equipment/quiver, target selection, cancellation,
save failure/retry, emergency-save prompt, direction prompt, file names,
confirmation and the continuation footer. The footer is centered using UTF-8
terminal-column width instead of a hard-coded English string length.

The store/home UI displays Chinese headings, purchase/withdraw prompts,
context menu actions and common errors (full inventory, insufficient money,
unavailable store). Crucially, **shop Buy/Sell labels are context-specific**:
the previous character-stat-point `Buy` and `Sell` labels continue to mean
increase and decrease a stat; the store independently displays 購買/出售.
Item counts, prices, object names, save data and command keys are unchanged.

Basic key-map/options labels and common command menu prompts also use
display-only labels. Translatable fixed messages use `msg("%s", translated)`
to preserve `-Werror=format-security` compatibility. This scope does not
include full combat narration, class title progression or all options text.

## CJK character-sheet and dynamic-menu layout fix (2026-11-03)

The native character sheet previously used `strlen()` (UTF-8 bytes) to
measure labels and values, and even passed the byte count as the text
length to `Term_putstr()`. It now calculates terminal display columns,
clips values to whole UTF-8 glyphs and renders strings without byte-count
truncation. Race/class names are still read from unchanged English data.

The native dynamic context menu also previously sized its dialog with
`strlen()`, which could overestimate Chinese labels and result in a
negative starting column on narrow screens. It now uses display columns
and bounds the menu width to the terminal. All command shortcuts, menu
selection indices, and gameplay data stay unchanged.

These are source-level changes with a host Unicode clipping regression
test; on-device visual checking in both ASCII and tile modes is pending.

## Spell menu and learning feedback (2026-11-03)

The original Angband spell menu displays Chinese prompts for spell selection,
book browsing and spell statuses. Spell learning and concentration failure
messages have Chinese variants. The average-damage browser header/footer is
localized, while the spells' underlying names, effect types and data remain
English. Every translated formatted message uses a language-specific literal
format string, preserving NDK format-security compilation.

## Item use and low-mana feedback (2026-11-03)

Use/charge/refill messages and prompts for wands, rods, staves, activatable
objects, lamps, and item inscriptions now include Chinese display text.
The mana shortage confirmation is translated, with English fallback.
The underlying item data, charges, effects, inscription content and
spell command filters are unchanged. Sound-bearing device activation uses
`msgt(snd, "%s", ...)` to preserve existing event types, and formatted
inscription prompts use literal per-language format strings to satisfy NDK
`-Werror=format-security`.

## Movement, terrain and stairs messages (2026-11-03)

The original Angband engine's common terrain interaction messages now have
Traditional Chinese display text, including open/close/lock doors, digging,
blocked walls, clearing webs, auto-exploration, and stairs. The underlying
movement, destination, terrain identifiers, event sound categories and player
state are untouched. Any messages with dynamic grammar or monster naming
remain in English until their templates can be translated safely.

## First combat feedback pass (2026-11-03)

Common player-attack messages are now Chinese: fear preventing an attack,
melee misses, shield bashes, stumbling, and ammunition or launcher errors.
The same fear template is used by movement into an enemy. Missile hit feedback
for a direct hit also has a Chinese variant. Each parameterized message uses
two language-specific *literal* format strings to satisfy Android NDK
`-Werror=format-security`. Original `MSG_*` event categories, hit chances,
damage amounts, monster names, ranged item labels and turn consumption are
unchanged. Complex verb-driven hit narration remains English pending a
grammar-aware formatter.

## Combat verb and critical-hit translation (2026-11-03)

Added a separate `zh-tw-combat.h` with *exact-match* melee/ranged verb
translations based on the original Angband 4.2.4 attack defaults and the
English `variant_lib/angband/gamedata/brand.txt` and `slay.txt` files,
plus the five known critical-hit descriptions. Only the rendered combat
message changes: `obj-slays.c`, monster names, effect data, event types,
damage numbers, attack rolls and savefiles are untouched.

When a verb (for example an uncommon shapeshift attack) or quality phrase
is not mapped, the *whole English message* is retained. This avoids
constructing grammatically misleading mixed Chinese and English templates
from unverified unknown verbs. The known monster or item name can still
appear in English inside an otherwise Chinese sentence until monster and
item grammar handling is addressed separately. All translated printf-style
message formats are literal strings compatible with NDK format security.
Standalone C99 tests cover known, unknown and null verb cases.

## Validation and remaining tasks

Run on a machine with Python 3, JDK 21 and a host C compiler:

```bash
sh scripts/verify-zh-tw.sh
```

This includes `GameTextLocaleTest`, standalone C tests for the death-menu tables, monster and item display names, UTF-8 display-column clipping/padding, and `scripts/check_native_game_localization.py`, which checks translation counts, fallback wiring and data isolation.

For a configured Android Studio environment with SDK/NDK, run:

```bash
sh scripts/verify-zh-tw.sh --android
```

Then test in a fresh zh-TW emulator: start Angband, check the monster/item list (`[` and `]`), inspect known object kinds and item flavors, and trigger the death/retirement menu using disposable save data. Repeat in English to verify fallback. Check movement keys, cursor alignment, long Chinese labels, save/load and graphics/ASCII modes. **No complete Android build or gameplay/emulator test has been completed for this batch.**

Next safe steps are to translate more verifiable non-unique monster names and item-kind labels, add locale-safe translations for command selection menus and message templates, and verify CJK two-column rendering across terminal textblocks, overlays and different emulator sizes. A larger translation of monster lore, item grammar and game descriptions needs language-aware formatting, not mechanical replacement of names in data files.
